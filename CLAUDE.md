## Design Decisions
- **Font:** Neue Montreal (via Fontshare CDN) — single font, weight 400 (regular) everywhere
- **Color:** Dark mode (#0a0a0a background, #1a1a1a surface, #f0f0f0 text, #888 muted). **Accent blue:** `#0094FF` (matches the blue in NOVA's AR UI — sampled from `images/nova-hud-text-example.png`). Used for legend circles, the HUD Text "Selected" image border, and Solution Evaluation Matrix highlighted-row accent + tint. When adding new blue accents, reuse `#0094FF` (or `rgba(0, 148, 255, ...)` for transparent variants) so the page stays unified.
- **Blue scope:** `#0094FF` is the **NOVA case study's** accent (it matches the AR UI). It should NOT bleed into page chrome that lives across the site — e.g. the side-nav active-state indicator uses `var(--text)` (white) instead of the blue, so the chrome stays neutral while the case-study content keeps its own brand voice.
- **Radius:** 8px globally via `--radius` CSS variable
- **Max-width:** 960px for case study content sections (coffee/pollen/ticker). Home work grid and Play grid are 1344px for a wider workshop feel.
- **Case-study hero spacing:** `.project-hero` top padding is **72px** and assumes a full-width cover image above it (all four case studies have one; the nav floats over the cover). If a future case study ever ships WITHOUT a cover, the heading will sit too close to the floating nav — either add a cover or give that page nav-clearance padding (~160px).
- **Nav:** Floating pill, 760px wide, glassmorphism blur (rgba(20,20,20,0.85)), centered. Links: Work | Play | About | Resume | Get in touch
- **Hero:** Animated mesh gradient (@property CSS). Text scramble reveal + magnetic tilt. No cursor glow. Hire-state pill `.status-tag` below the subtitle reads "Open to new opportunities" with a `.status-dot` (green #4ade80, soft `pulse` animation that breathes opacity 0.7↔1.0 over 3s ease-in-out — deliberately *not* a scale+opacity blink; calm "alive" signal, not nervous). When Chang lands a role, swap the pill copy (e.g. "Open to interesting conversations") or remove `.status-tag` entirely. **Hero gradient variant system (2026-06-15):** the gradient lives on `.hero-orbs` as swappable variant classes. `.hero-orbs--g1` = the original animated violet/coral mesh (rgba(100,70,220)/coral/purple/peach, `meshFlow` 12s), **saved and restorable**. `.hero-orbs--g2` = the **ACTIVE** gradient (HTML: `<div class="hero-orbs hero-orbs--g2">`): a vivid full-neon iridescent spectrum from a reference image — **warm at the top** (yellow #FFD600 → red → pink) flowing into a strong **blue** (rgba(22,120,255)) behind the heading; **only the 4 bright hues, no teal/green/violet edge tones**. It's "alive" via @property-animated blob positions (`irisFlow` 15s) that drift + a scale-breathe (mirrors g1's motion). To revert to the old look, swap the class back to `hero-orbs--g1`. The `.hero-sub` and `.status-tag` were brightened for legibility over g2 (subtitle → rgba(255,255,255,0.82); pill → 0.92 white text + dark glass backdrop `rgba(10,10,12,0.45)` blur(8px) + 0.22 border). **Decision history — do not re-litigate:** iterated muted → vivid → "not that vivid" → full-neon WARM-top → and on **2026-06-15 pushed warmer still to WARM-DOMINANT** ("as warm as the footer": warm fills the body + behind the heading, blue eased back/down behind the subtitle). User **rejected the extreme** (warm covering ALL the text with blue only as a thin bottom-edge band — "too much") and the earlier over-soft/washed versions. **Motion was reworked livelier the same day** (`irisFlow` now 13s): blob travel widened to ~±12% and the **yellow now animates too** (it was pinned), because the first pass "did not feel alive". **Then reverted to BALANCED and refined (current shipped state, 2026-06-15):** the warm-to-blue cut now lands right **under the FIRST heading line** — "AI-first product designer." glows on warm, while "Building what's next." + the subtitle + pill sit crisp on blue (the `irisFlow` centers that produce this: warm-y ~25, pink-y ~48, blue-y ~78; the two headline lines split at ~box-Y 57%). A subtle heading text-shadow is the lever if the first line ever needs more crispness over the warm. **Mobile (≤768px) fixes (2026-06-15):** the short mobile hero compresses the g2 gradient and lands the blue blob low, so it met the dark work section with a visible **cut / dividing line**. Fixed two ways: (a) `.hero-orbs { bottom: 8% }` (was `-12%`, which shoved the blue to the very bottom edge where `overflow:hidden` clipped a ~4%-opacity sliver into a faint line) pulls the blue up — also makes it more visible; **and** (b) a `.hero::after` overlay (`linear-gradient(to bottom, transparent, #0a0a0a 78%)`, `height: 42%`, `z-index: 1` — above orbs/0, below text/2) fades the hero's bottom to the **EXACT page bg** so the gradient dissolves seamlessly into the work section with **no clipped residual**. (A `mask-image` on the orbs was tried first and abandoned: a mask leaves a clipped-residual line because it makes the orbs transparent rather than painting the bg; the overlay paints `#0a0a0a` so the hero edge and work section are the same color — seamless.) Both mobile-only; **desktop is untouched** (`::after` is `none`, orbs use base `bottom:20%`). Also **mobile `.hero h1` is `clamp(26px, 8.5vw, 32px)`** (was a flat `32px`): keeps ~32px on standard phones (≥375px) but scales down on narrow screens (30.6px@360, 27.2px@320) so the first line "AI-first product designer." keeps its period on **one line** instead of orphaning it (each char is an inline-block, so the line can break right before the "."). **Open thread — hero vividness (diagnosed, NOT applied):** the hero looks less vivid than the footer because it's blurred radial blobs (`filter: blur(56px)`) while the footer is a crisp un-blurred *linear* gradient — same palette, but the blur averages the hero's colors down. - **About photo deck** (`.deck` / `.deck-track` / `.deck-card` in `about.html` + inlined IIFE, added 2026-05-29): infinite editorial carousel of the 8 personal photos with three composable behaviors — **always-on auto-rotate + drag-to-rotate + an always-on hover "light shimmer" tilt**. Markup triples the 8 cards (24 total) so a full set always bleeds off both edges. Built from a reference (pearl-social-nine.vercel.app) but **adapted**: the reference hijacks the mouse-wheel because its carousel IS the whole viewport (`h-screen`, page non-scrollable); our deck sits mid-page, so wheel-hijack would trap scrolling. **We use drag-to-rotate instead** — a direction-intent guard commits to a horizontal drag (grab + momentum flick, friction 0.92) but releases vertical gestures back to the page (`touch-action: pan-y`), so scrolling is never trapped. Mechanics: continuous drift `SPEED = 48` px/sec via rAF with a sub-pixel accumulator (`acc += SPEED*dt`; `Math.floor` into `scrollLeft` so it never stutters) — **the drift NEVER pauses** (see history); seeded-middle on first paint (`offsetLeft + offsetWidth/2 - clientWidth/2`, in the load handler so no flash); symmetric wrap at `>=2*setWidth` / `<setWidth`. Per-frame magnetic focus (`focus = max(0, 1 - dist/halfSpan)`, `halfSpan = trackWidth*0.28`) written as `--focus` and driving `scale(0.82 + 0.22*focus)`, `opacity(0.62 + 0.38*focus)`, **squared**-falloff drop-shadow + warm-coral halo (`rgba(255,150,120,…)`, matches the footer-glow palette — deliberately NOT the reference's gold). **Hover tilt ("light shimmer"):** a global cursor (`mouseX/Y/mouseOver`) is tracked, and every frame `paintCards()` resolves which card the cursor is over and tilts it in 3D toward the pointer (`--tilt-rx/ry`, ±`TILT_MAX=11`°, lerped `0.14`) — recomputed per frame so the tilt tracks the cursor AND the drifting cards (the card shimmers as it passes under a still cursor; deck keeps moving). Requires `perspective: 900px` on `.deck-track` (the cards' DIRECT parent) — `overflow` forces `transform-style:flat`, so a preserve-3d chain from `.deck` can't reach the cards; without direct-parent perspective the tilt flat-skews ("just leans left"). Cards face flat at rest (rotate 0). Bottom-fade `mask-image` dissolves the deck into the page (use `filter: drop-shadow`, not `box-shadow`, so it renders through the mask). Sits at a balanced gap below the hero via `.deck { margin-top: -84px }` (pulls up into the hero's empty bottom padding so heading→deck ≈ heading→header; the shared `.page-hero` is untouched) — the mobile block resets this to `margin-top: 0` because the mobile hero is much shorter and -84px drags the grid into the heading. `.deck-track` uses `overflow-x: scroll; overflow-y: hidden` — the explicit `hidden` is required because `overflow-x:scroll` would otherwise force `overflow-y:auto`, making the deck a vertical scroll-container that traps the page's wheel. **Mobile (≤768px): the JS bails immediately** (`matchMedia('(max-width: 768px)')` → add `is-ready`, `return`) and CSS collapses the same markup to the original static 4×2 grid (`.deck-card:nth-child(n+9){display:none}` hides the 2 duplicate sets) — no drift/drag/tilt. Respects `prefers-reduced-motion` (static scrollable row). Deliberate exception to the "no motion on About" preference (which still holds for Skills/Tools chips) — the deck IS the focal surface here. **History (don't re-add the PAUSE):** a hover-*pause* (deck freezes on hover so you can hold-and-tilt a card, via a `driftFactor` eased 0↔1) was tried twice and removed — even eased, stopping/resuming the drift was the source of every "jump"/jolt the user reported. Decision (2026-05-29, after several back-and-forths): **the drift must never stop.** The hover tilt simply plays over the moving cards; at 48px/s a card crosses the cursor slowly enough to see the tilt without needing a pause. Keep it no-pause.
